2026 年，AI 世界发生了一件奇怪的事。

过去几年，人们一直在努力让大语言模型变得更聪明。

从 GPT 到 Claude，从 DeepSeek 到 Qwen，模型的参数规模越来越大，推理能力越来越强，能够解决的问题也越来越复杂。

### 2. 为什么不能直接让它一次预测一百个 Token？

林远不服气。

这就是自回归模型采用顺序生成的一个重要原因。

后面的语言，依赖前面已经确定的语言。

当然，这并不意味着并行生成完全不可能。

推测解码、多 Token 预测、块级生成等技术，都在尝试减少顺序执行的开销。

但研究人员开始思考一个更加激进的方案。

既然逐 Token 生成存在顺序瓶颈……

为什么一定要从左到右生成？

“有些方法使用连续空间扩散，有些使用不同的离散状态转移，还有一些采用分块生成。”

### 2. 扩散语言模型的数学直觉

对于一种简化的掩码扩散过程，可以把训练分成三步：

1. 从训练文本中抽取完整序列。
    
2. 随机选择噪声水平，遮盖一定比例的 Token。
    
3. 训练模型根据未遮盖的上下文，预测被遮盖的内容。
    

模型学习的是类似下面的条件分布：

\[ p_\theta(x_{\text{masked}}\mid x_{\text{visible}},t) \]

这里的 \(t\) 表示噪声水平或扩散阶段。

与标准自回归模型不同，掩码位置的预测可以利用左右两侧已经可见的上下文。

不过，在生成阶段，如果多个位置同时预测，仍可能出现相互矛盾的问题。

因此，模型通常需要多轮修正、重新掩码或者逐步确定部分 Token。

扩散语言模型不是没有顺序计算，而是把逐 Token 的顺序依赖，改造成多轮文本精炼。

陈默列出了四个关键因素：

## 第五幕：一个致命的反击——KV Cache

当天晚上，团队召开技术讨论会。

负责传统大模型推理的工程师周航提出了反对意见。

“你们把自回归模型想得太落后了。”

林远一时语塞。

KV Cache。

### 1. 自回归模型为什么需要缓存？

假设模型已经生成：

> Java 中的 HashMap 底层使用……

现在它准备生成下一个 Token。

如果每次都重新计算之前所有 Token 的注意力相关投影，开销会很大。

因此，Transformer 解码器可以缓存之前 Token 的 Key 和 Value。

下一步生成时，只需要计算新 Token 对应的内容，并使用已有缓存参与注意力计算。

KV Cache 的基本工作方式

历史 Token

缓存 K、V

新 Token

计算新 K、V

利用历史缓存完成当前注意力计算

周航继续说：

“你们的扩散模型如果每一轮都重新处理整个生成块，未必比我的增量解码便宜。”

陈默回答：

“所以扩散语言模型仍然面临计算复用、缓存设计和精炼调度等工程挑战。”

“但反过来，自回归模型也没有消除逐 Token 的串行依赖。”

两人对视一眼。

他们终于意识到：

这不是一种技术彻底淘汰另一种技术的战争，而是两套不同计算结构之间的竞争。

## 第七幕：扩散模型真的能随意修改中间内容吗？

林远突然提出一个问题。

|比较维度|自回归语言模型|掩码扩散语言模型|
|---|---|---|
|生成方式|按顺序逐 Token 生成|多轮恢复或精炼 Token|
|顺序依赖|输出存在严格的前缀依赖|通常按精炼轮次推进|
|并行生成|受顺序解码限制|可同时预测多个位置|
|上下文使用|因果注意力为主|可利用已知位置的双向上下文|
|KV Cache|增量解码生态成熟|缓存复用方式依架构而异|
|推理延迟|受 Token 数和解码速度影响|受轮次、块大小及单轮成本影响|
|代码编辑|已有成熟工程生态|具有潜力，但需任务验证|
|长文本生成|生态成熟，支持流式输出|长度扩展、分块与质量控制仍是挑战|
|典型代表|GPT、Claude 等|Mercury、LLaDA 等扩散路线|

陈默看完报告，问了最后一个问题。

“所以，扩散语言模型会取代 GPT 吗？”

林远想了很久。

然后回答：

“现在不能这么说。”

“自回归模型的优势不只是生成质量，还有成熟的推理基础设施、工具调用能力和工程生态。”

“扩散模型则尝试用不同的计算结构，改善某些场景下的生成效率。”

“未来可能是两条路线竞争，也可能是混合架构。”

陈默笑了。

“这次你终于没有被一个新的模型名字带着走。”

## 第二章·技术总结

第一：自回归模型的瓶颈不是不能并行计算。

而是标准生成过程需要依赖此前已经确定的 Token。

第二：扩散语言模型不是一次性完成所有生成。

它通常需要多轮预测与精炼，用更少的顺序轮次换取更多位置的并行处理。

第三：生成轮次少不等于推理成本低。

必须同时考虑每轮计算量、缓存复用、输出质量、吞吐与硬件效率。

第四：Mercury 类路线的价值在于探索不同的语言生成机制。

它不只是一个更快的模型名称，而是对逐 Token 生成范式的挑战。
