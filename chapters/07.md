照片中，一只橘猫正坐在桌子边缘。

### 1. 图像识别解决的是“是什么”

早期计算机视觉的发展，主要围绕几个问题展开。

图像分类回答：

> 这张图片里是什么？

目标检测回答：

> 物体在哪里？

图像分割回答：

> 哪些像素属于这个物体？

这些能力极其重要。

但它们并不自动等于对物理世界的完整理解。

陈默写下三个问题：

第一个问题：是什么？

这是识别。

第二个问题：在哪里？

这是空间理解。

第三个问题：如果我采取某个动作，会发生什么？

这是预测与决策。

“而 World Model 的核心目标之一，就是让系统能够处理第三类问题。”

### 2. 为什么第三类问题更难？

林远回答：

“因为未来还没有发生。”

“对。”

“你不能只靠观察当前状态。”

“你需要根据当前世界状态、可能的动作，以及环境变化规律，推测未来状态。”

陈默在白板上写下：

\[ s_{t+1}=F(s_t,a_t) \]

其中：

- \(s_t\)：当前世界状态
    
- \(a_t\)：当前执行的动作
    
- \(F\)：世界的状态转移规律
    
- \(s_{t+1}\)：执行动作后的状态
    

“这只是最简单的形式。”

“真实世界还存在噪声、未知因素和部分可观测性。”

“所以更一般地，我们要学习一个概率预测模型。”

\[ p(s_{t+1}\mid s_t,a_t) \]

林远盯着公式。

“等等，这不就是强化学习里面的状态转移模型？”

陈默笑了。

“你终于发现它们之间的联系了。”

### 1. 什么是 World Model？

世界模型并不是某一个固定的神经网络结构。

它是一类能够表示环境状态、预测环境变化，或支持行动规划的模型。

陈默写下一套简化结构：

环境观测

图像、视频、传感器、动作历史

状态编码器

把观测转换成内部状态表示

动态预测模型

预测不同动作造成的未来变化

规划与行动

选择更有可能完成目标的动作

林远说：

“也就是说，AI 可以先在内部模拟一次，再决定是否真的执行。”

“对，这是一种很重要的应用方式。”

“但不是所有世界模型都显式执行完整的规划，也不是所有世界模型都能准确预测物理过程。”

### 2. 从观测到隐状态

陈默继续解释。

“真实世界的状态可能非常复杂。”

“假设一个机器人看见玻璃杯。”

它能观察到杯子的颜色和轮廓。

但可能看不到杯子背面。

不知道杯子里装了多少水。

也不知道杯底与桌面之间的摩擦系数。

“所以机器人获得的往往不是完整世界状态，而是部分观测。”

可以写成：

\[ o_t=G(s_t) \]

其中 \(o_t\) 是观测。

模型通过历史观测构造内部表示：

\[ z_t=E(o_{\leq t},a_{<t}) \]

然后预测：

\[ \hat z_{t+1}=F_\theta(z_t,a_t) \]

“这里的 \(z_t\) 可以理解成模型对当前环境的内部表示。”

“它不一定是人类可以直接读懂的三维地图。”

林远问：

“那为什么不直接预测下一张图片？”

陈默回答：

“可以。”

“但并不是所有任务都需要生成完整图片。”

“如果只是判断杯子是否会掉落，预测位置、速度或接触状态，可能更高效。”

## 第三幕：二维照片，如何变成三维世界？

陈默回答：

“这是三维视觉长期研究的问题。”

### 1. 二维图像丢失了深度

在真实世界中，一个物体的位置可以用三维坐标表示：

\[ P=(x,y,z) \]

但普通照片通常是把三维世界投影到二维图像平面。

在简化的针孔相机模型中：

\[ u=f_x\frac{X}{Z}+c_x \]

\[ v=f_y\frac{Y}{Z}+c_y \]

其中：

- \((X,Y,Z)\)：相机坐标系中的三维点
    
- \((u,v)\)：图像上的像素位置
    
- \(f_x,f_y\)：相机焦距相关参数
    
- \(c_x,c_y\)：主点坐标
    

陈默问：

“如果只知道像素位置 \(u,v\)，能唯一确定三维点吗？”

林远思考后回答：

“不能，因为深度 \(Z\) 未知。”

“没错。”

“同一个像素位置，可能对应不同距离上的物体。”

这就是为什么从单张图片恢复三维结构存在天然歧义。

## 第四幕：世界模型与视频生成——看起来很像，目标却不同

林远兴奋地说：

“这不就是世界模型吗？”

陈默没有立即回答。

他把视频倒放了一遍。

然后问：

“这段视频很真实吗？”

“很真实。”

林远迟疑了。

“不一定。”

“对。”

### 1. 视频逼真不等于物理正确

视频生成模型通常学习视频数据中的时空统计规律。

它可能学会：

杯子掉落通常会向下运动。

玻璃碰撞地面可能碎裂。

水洒出来会向四周流动。

但它也可能出现：

物体突然变形。

物体数量不守恒。

接触关系错误。

运动轨迹不合理。

“模型能够生成视觉上合理的视频，并不意味着它拥有精确的物理模拟器。”

陈默说。

### 2. 物理模拟器又是什么？

传统物理引擎通常显式使用物理规则计算物体运动。

例如：

\[ F=ma \]

\[ v_{t+\Delta t}=v_t+a_t\Delta t \]

\[ x_{t+\Delta t}=x_t+v_t\Delta t \]

“这些公式只是最基础的运动关系。”

“实际物理引擎还要处理刚体碰撞、摩擦、约束、接触和数值稳定性。”

林远说：

“所以物理模拟器是按照已知规律计算，而学习型世界模型主要从数据中学习预测规律。”

“这是一个有用的区分。”

“不过两者可以结合，例如让神经网络预测难以显式建模的部分，再用物理引擎执行约束计算。”

### 3. 三种系统的区别

|系统|主要目标|核心能力|典型局限|
|---|---|---|---|
|视频生成模型|生成合理的视频|视觉与时间连续性|物理一致性未必可靠|
|物理模拟器|计算给定规则下的运动|明确的动力学与约束|难以覆盖真实世界全部复杂性|
|World Model|预测环境变化并支持决策|状态表示、未来预测、规划|数据偏差、误差累积|

陈默补充：

“它们不是互斥的类别。”

“一个视频预测模型可以成为世界模型的组成部分。”

“一个世界模型也可以结合物理模拟器。”

“关键要看系统能否可靠地回答：如果采取某个动作，环境会怎样变化？”

## 第五幕：动作条件预测——世界模型真正的分水岭

林远重新打开玻璃杯视频。

这次，他提出一个新要求。

“如果机器人不是把杯子向左推，而是向右推呢？”

视频生成模型又生成了一段视频。

但陈默问：

“这两段视频的差异，真的由动作控制了吗？”

林远愣住。

“难道不是？”

“不一定。”

“仅仅生成一段符合提示词的视频，不等于系统能在相同初始状态下可靠地比较不同动作的后果。”

陈默在白板上写下：

\[ p(o_{t+1}\mid o_{\leq t},a_t) \]

“这叫动作条件预测的一种表达方式。”

“模型不仅接收过去的观测，还接收动作。”

“它要学习的是，动作如何影响未来。”

### 1. 没有动作条件的预测

模型看到：

> 杯子正在向桌边滑动。

预测：

> 杯子可能掉落。

这是对自然演化的预测。

### 2. 有动作条件的预测

模型看到：

> 杯子静止在桌上。

同时输入动作：

> 机械臂向左推动 5 厘米。

预测：

> 杯子向左移动，并可能接近桌边。

换一个动作：

> 机械臂向右推动 5 厘米。

预测：

> 杯子向右移动，远离桌边。

“这样，系统就可以比较不同动作的预期结果。”

陈默说。

“这为规划提供了基础。”

### 3. 在脑海中试错

林远突然兴奋起来。

“那机器人是不是可以先模拟一百种动作？”

“然后选择最好的？”

“理论上可以采用类似策略。”

陈默写下：

\[ a^*=\arg\max_a \mathbb{E}[R(\hat s_{t+1})\mid s_t,a] \]

“这里的 \(R\) 表示目标收益。”

“例如，让杯子移动到指定位置，同时避免碰撞。”

“但实际规划可能需要考虑多步动作序列，而不是只看下一步。”

这就引出了一个重要方法：

Model Predictive Control，模型预测控制。

## 第六幕：MPC——先预测，再行动，再修正

![Black Forest Labs učí roboty chápat svět a plánovat další pohyb | Jarvis AI](https://images.openai.com/static-rsc-4/LVAYzVvkKzutpyiiS8qTt-ys1FIbgT4_Nww8y4uQae-tJMEvXixsP4Efe9B1ujjs79RjtRva-2Vl3qhdiwz8g7HQY5msBY6tJm7hDFxJP7fAP7aJku3nhkanb62nqMs9R-AnqO2ke9OUF3jNdxMjpeV7DD_XJ5WAoy4zjprNNNs?purpose=inline)

[jarvis-ai.cz](https://www.jarvis-ai.cz/black-forest-labs-uci-roboty-chapat-svet-planovat-dalsi-pohyb)

陈默给林远展示了一套机械臂控制系统。

机械臂需要把杯子从桌子左侧移动到右侧。

系统首先生成多个候选动作序列。

然后使用模型预测每个序列的结果。

选出最优方案。

但它不会一次性执行完整个方案。

它只执行前面一小步。

随后重新观察世界，再规划下一步。

林远问：

“为什么不直接执行全部动作？”

陈默回答：

“因为预测会出错。”

“现实环境也可能发生变化。”

“所以我们要不断利用真实观测纠正模型。”

观察当前状态

预测多个动作序列的未来结果

选择最优动作序列

只执行当前一小步

重新观察并滚动规划

“这就是滚动时域优化的基本思想。”

陈默说。

“它在机器人、自动驾驶和工业控制中都有重要应用。”

“但具体控制频率、预测模型和安全约束，需要根据任务设计。”

林远思考了一会儿。

“这和 Agent 的 ReAct 循环有点像。”

“哪里像？”

“都是观察、决策、执行、再观察。”

“非常好。”

陈默点头。

“只是机器人面对的是连续物理世界，而 Coding Agent 主要面对离散的软件环境。”

“它们的共同点，是都需要在行动后利用反馈修正决策。”

## 第七幕：具身智能——AI 终于拥有身体

![新知 - 大圆镜｜给机器人装“隐形眼睛”，0.9B参数搞定精细操作](https://images.openai.com/static-rsc-4/stXfwk5PebF3vyR7-79Rv7p1fnlFqwaMXRdLlpAIx_OrU-QYn6VJJw0SFrrxufZBr1pUBnajc99llzZp3e9jS96WXX3kEoEHhVHY_kTut4l1HHxkeH83xln__JyZLaf-4C3qx2dEKresMjtAm5f-xsp6J1Igkri7X8w7dhPLk2Q?purpose=inline)

[dyj.live](https://www.dyj.live/knowledge/story_id-gm_explore-261ef621-4c96-5bb6-878a-a257b0c3675e)

一个月后。

林远来到一家机器人实验室。

实验室里有一台双臂机器人。

它正在学习把杯子放进洗碗机。

第一次尝试，失败。

第二次尝试，杯子掉落。

第三次尝试，机械臂碰到了洗碗机门。

第四次尝试，终于成功。

林远问：

“为什么这比让 LLM 写一段 Java 代码难这么多？”

陈默回答：

“因为代码世界和物理世界的反馈性质不同。”

“代码执行通常有相对明确的接口、错误信息和测试结果。”

“而机器人需要面对连续空间、传感器噪声、接触力、摩擦、硬件延迟和真实物理风险。”

### 1. 什么是具身智能？

具身智能，Embodied AI，强调智能体通过身体与环境进行感知和行动。

它不仅需要回答：

> 桌子上有什么？

还需要完成：

> 把桌子上的杯子拿起来。

这要求系统具备多种能力：

感知物体位置。

理解空间关系。

规划运动轨迹。

控制机械臂。

利用触觉或视觉反馈修正动作。

“所以具身智能不是给语言模型装上一个机器人外壳。”

陈默说。

“它涉及感知、规划、控制、学习与硬件系统的深度结合。”

### 2. 机器人为什么需要多种传感器？

林远看着机器人。

“它已经有摄像头了，为什么还需要触觉传感器？”

陈默拿起一个玻璃杯。

“假设你闭上眼睛，拿着杯子。”

“你怎么知道自己有没有握紧？”

“通过手指感受到的压力。”

“对。”

“仅靠视觉，很难准确判断所有接触力。”

机器人可能使用：

- RGB 摄像头
    
- 深度相机
    
- 力矩传感器
    
- 触觉传感器
    
- 关节编码器
    
- IMU 惯性测量单元
    

“这些传感器提供不同类型的信息。”

“系统需要把它们融合起来，才能更可靠地控制身体。”

## 第八幕：VLA——视觉、语言与动作终于连接起来

林远继续观察机器人。

工程师对机器人说：

> 把桌子上的红色杯子放进右边的篮子。

机器人先观察桌面。

识别红色杯子。

然后伸出机械臂。

抓取。

移动。

放下。

林远问：

“这是不是把视觉模型、LLM 和机械臂控制器拼起来？”

陈默回答：

“可以采用模块化方案，但还有另一条重要路线。”

Vision-Language-Action，VLA。

### 1. VLA 的基本思想

VLA 模型尝试把视觉观测、语言指令与机器人动作联系起来。

简化形式：

\[ a_t=\pi_\theta(o_t,l,h_t) \]

其中：

- \(o_t\)：视觉或其他传感器观测
    
- \(l\)：语言任务指令
    
- \(h_t\)：历史信息
    
- \(a_t\)：输出动作
    

林远问：

“它输出的是文字吗？”

“不一定。”

“它可以输出动作 Token、关节目标、末端执行器位姿，或者一段动作序列。”

“具体取决于模型设计和机器人控制接口。”

### 2. 从语言 Token 到动作 Token

陈默写下：

传统语言模型：

```
输入：解释如何拿起杯子
输出：先靠近杯子，然后抓取……
```

VLA 系统：

```
输入：
视觉观测 + “拿起红色杯子”

输出：
机械臂末端目标位置
夹爪开合动作
后续动作序列
```

“语言模型会告诉你应该怎么做。”

“VLA 则尝试直接生成可以被机器人执行的动作表示。”

林远点头。

“这就是从理解指令到执行动作。”

### 3. VLA 与 World Model 的区别

陈默问：

“VLA 一定需要显式世界模型吗？”

林远想了一下。

“不一定？”

“对。”

“有些 VLA 可以直接从观测映射到动作。”

“有些系统则把世界模型用于预测和规划，再由控制策略执行。”

|维度|VLA|World Model|
|---|---|---|
|核心问题|当前应该做什么动作？|某个动作会导致什么结果？|
|主要输出|动作或动作序列|未来状态、观测或特征|
|典型用途|机器人操作|预测、规划、仿真|
|是否必须结合|不必须|不必须|
|组合价值|用预测结果改善动作选择|为策略提供未来信息|

陈默总结：

“VLA 更接近行动策略。”

“World Model 更接近环境预测。”

“它们可以组合，但不能直接画等号。”

## 第九幕：世界模型如何训练？

夜里十一点。

林远回到办公室。

他打开训练脚本。

“陈工，既然世界模型需要预测未来，我们是不是只要收集大量视频就行？”

陈默摇头。

“视频很重要，但还不够。”

### 1. 被动观察数据

最简单的训练方式之一，是从视频中学习未来预测。

例如：

输入过去几帧。

预测下一帧，或预测未来的潜在特征。

```
Frame 1
Frame 2
Frame 3
   ↓
World Model
   ↓
Predicted Frame 4
```

这种训练可以帮助模型学习运动和时间结构。

但存在一个问题。

“什么问题？”林远问。

“如果你没有记录动作，模型就很难区分某个变化是由什么行动引起的。”

### 2. 动作条件数据

因此，机器人世界模型往往需要这样的数据：

```
当前观测
   +
机器人执行的动作
   +
执行后的观测
```

例如：

```
{
  "observation": "杯子位于桌子中央",
  "action": "机械臂向左推动 5 厘米",
  "nextObservation": "杯子向左移动"
}
```

“这类数据能帮助模型学习动作与状态变化之间的关系。”

陈默说。

“不过要注意，观察数据中的相关性不一定等于因果关系。”

“模型能否在新环境中可靠预测动作后果，需要专门评估。”

### 3. 模拟环境训练

林远问：

“真实机器人采集数据太贵了，怎么办？”

陈默回答：

“可以使用仿真。”

在模拟环境中，机器人可以反复尝试。

失败不会摔坏真实设备。

也更容易生成大量训练轨迹。

但这里有一个经典问题：

Sim-to-Real Gap，仿真到现实的差距。

仿真中的摩擦、接触、光照和传感器噪声，不可能与现实完全一致。

因此，模型在模拟环境里表现优秀，不意味着直接部署到现实就一定可靠。

## 第十幕：世界模型的致命弱点——预测越远，错误越大

![The Future is AI's Proof of Work | Back Alley Coder](https://images.openai.com/static-rsc-4/rpnW0MeJiJph00u6qn950PK9GK536hE2y_P7nXjTDZuJ0dzjgriBnQkiD5sv6SAFQO-wLHxFr_fYnSbwQolCrxNyDurPIJwdA5WL8RVR__OrXUwx6bCR-B4_usjL0nr0d6O1aWjr0D5pyZURavav-P2YIZoh8AQUPSQtsDPGshw?purpose=inline)

[backalleycoder.com](https://backalleycoder.com/posts/the-future-is-ai-proof-of-work/)

林远终于训练出了自己的第一版世界模型。

它能够预测机械臂推动杯子后的短期运动。

第一步预测，很准确。

第二步预测，也不错。

第五步，开始出现偏差。

第十步，杯子的位置明显错误。

第二十步，杯子甚至穿过了桌面。

林远皱起眉头。

“为什么短期预测这么好，长期预测却越来越差？”

陈默回答：

“因为预测误差会累积。”

### 1. 误差累积

假设模型每一步预测都存在一点误差。

下一步预测又依赖上一步的预测结果。

那么，误差可能逐渐扩大。

这被称为多步滚动预测中的误差累积。

“尤其在接触、碰撞和不稳定运动中，小误差可能造成完全不同的结果。”

陈默说。

“例如杯子到底有没有碰到桌边，可能决定它是继续留在桌上，还是直接掉落。”

### 2. 不确定性比单一答案更重要

林远问：

“那是不是应该让模型输出多个未来？”

“这是重要方向之一。”

同一个初始状态和动作，可能产生多种结果。

例如，机器人抓杯子：

- 成功抓起
    
- 杯子滑落
    
- 杯子倾斜
    
- 夹爪未接触到杯子
    

如果模型只输出一个最可能的未来，可能掩盖风险。

因此，一些世界模型会尝试预测未来状态的分布，而不是唯一确定的结果。

陈默说：

“真正安全的系统，不应该只问最可能发生什么。”

“还要问：最坏可能发生什么，以及模型有多不确定。”

## 第十一幕：从机器人世界模型到软件世界模型

林远突然提出一个问题。

“陈工，World Model 一定要用于机器人吗？”

陈默看了他一眼。

“为什么这么问？”

“因为我们做的是 Coding Agent。”

“它也需要预测执行某个动作之后，软件系统会发生什么。”

陈默笑了。

“你终于把今天的知识和自己的工程联系起来了。”

### 1. Coding Agent 也需要预测行动后果

假设 Coding Agent 准备修改一个 Java 方法。

它需要判断：

修改方法签名，会不会影响其他调用方？

增加数据库索引，会不会影响写入性能？

调整线程池参数，会不会造成资源竞争？

删除一个配置项，会不会影响生产环境？

“这些问题，本质上都涉及对行动后果的预测。”

陈默说。

“但这里要区分广义的环境模型思想和狭义的、经过专门训练的 World Model。”

“一个 Coding Agent 利用代码分析、测试和历史经验推测修改影响，并不意味着它内部已经拥有机器人研究意义上的世界模型。”

### 2. 软件世界中的行动闭环

观察代码仓库

预测修改影响

依赖关系、测试风险、行为变化

在隔离工作区执行修改

运行编译、测试和静态分析

根据真实反馈修正下一步

林远说：

“所以单纯预测还不够。”

“需要执行和验证。”

“没错。”

“尤其在软件工程里，编译器、测试框架和静态分析器能提供相对可靠的反馈。”

“相比完全依赖模型想象代码修改后的结果，直接运行测试往往更有价值。”

## 第十二幕：世界模型不是万能的

实验室终于完成了新一轮机器人测试。

机械臂成功抓起玻璃杯。

缓慢移动。

放到指定位置。

林远兴奋地鼓掌。

但陈默并没有宣布胜利。

他拿来一个形状不同的杯子。

机器人抓取失败。

换成装满水的杯子。

机器人又出现了偏差。

陈默问：

“为什么？”

林远回答：

“因为训练数据覆盖不够。”

“还有呢？”

“物体材质、重量、摩擦、光照、传感器误差，都可能造成分布变化。”

陈默点头。

“这就是世界模型面临的现实限制。”

它可能存在：

泛化问题。 在训练环境中有效，换到新环境就失效。

物理一致性问题。 预测结果看起来合理，却违反真实物理约束。

长期误差累积。 预测步数越多，不确定性可能越大。

部分可观测性。 仅靠当前传感器无法确定全部环境状态。

行动安全问题。 错误预测可能造成真实物理损害。

评测困难。 视频逼真度、预测准确率和实际任务成功率不是同一个指标。

“所以真正的机器人系统仍然需要安全约束、反馈控制、异常检测和必要的人工监督。”

陈默说。

“世界模型可以提高规划能力，但不能替代整个控制系统。”

## 第七章：技术归档

|技术|核心问题|典型应用|
|---|---|---|
|图像分类|这是什么？|物体识别|
|目标检测|物体在哪里？|场景感知|
|三维重建|空间结构是什么？|机器人定位、场景建模|
|World Model|环境将如何变化？|预测、规划|
|Action-conditioned Prediction|某个动作会导致什么？|机器人操作|
|视频生成模型|生成什么样的未来画面？|视频合成、预测|
|物理模拟器|已知物理规则下如何运动？|仿真、控制|
|MPC|如何滚动预测和行动？|机器人、自动驾驶|
|Embodied AI|如何通过身体与环境交互？|具身智能|
|VLA|如何从视觉和语言生成动作？|机器人策略|
|Sim-to-Real|仿真经验如何迁移现实？|机器人训练|

### 本章最重要的五个结论

第一：识别世界不等于理解世界的变化。

图像分类和目标检测回答的是当前画面中的信息，而世界模型进一步关注环境状态及其演化。

第二：World Model 的核心是预测。

尤其是动作条件预测：如果采取某个动作，未来可能发生什么。

第三：视频生成、物理模拟和世界模型有联系，但不能画等号。

视频逼真不保证物理正确，物理模拟也不自动拥有从复杂观测中学习和泛化的能力。

第四：VLA 与 World Model 可以相互补充。

VLA 负责生成动作，世界模型可以帮助评估动作后果。

第五：预测必须与真实反馈结合。

无论机器人还是 Coding Agent，可靠执行都不能只依赖模型对未来的想象。
